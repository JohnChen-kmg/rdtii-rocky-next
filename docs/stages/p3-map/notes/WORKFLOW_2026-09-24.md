**The shape of the money.** Steps S0 to S2 and S6 to S10 are free and deterministic. Everything paid sits
in S3, S4 and S5, and what reaches them is decided entirely by S2's caps. That is why the caps, not the
corpus size, set the bill.

## 0.1 The instrument, and which step reads which part

The instrument is the codebook. It is not a model and it is not data: it is the written rules the model
is made to follow, plus the labelled examples the retrieval uses as queries. Five files, and each step
reads a different one.

| File | What is in it | Read by |
| :---- | :---- | :---- |
| `indicator_order.yaml` | The 62 host IDs in host order, with pillar, name, status, evidence type, template row. Top-level keys for out-of-scope, non-regulatory, practice-based and `host_mapping_traps` | The indicator list everywhere. Today the code has a hard-coded list instead |
| `indicators.yaml` | One block per indicator: `question`, `definition`, `scoring`, `scoring_tree`, `coding_rules`, `exceptions`, `disambiguation`, plus `tier` and `review_notes` | **S4**, rendered into the cached system prefix. `review_notes` is never rendered |
| `policies.yaml` | Cross-cutting rules: `scoring_policy` with the polarity lists, `measure_inclusion`, `citation_contract`, and `edge_cases` such as `repealed` and `amending_act_cited_instead_of_principal` | **S4** in the prefix; **S9** for the zero-score filters |
| `signatures\<ID>.yaml` | Retrieval material: `keywords`, `definition_text`, `exemplar_law_types`, `scope_patterns`, `negative_signals`, and labelled `exemplars` with `exemplar_for` | **S1** to build the query; **S3** for the triage definitions |
| `gold\gold_set.jsonl` | The host's own coded rows. 51 in Round 1, 1,054 now, across ten economies | **S2** recall gate, **S10** evaluation. Never a decision input |

The split matters. `indicators.yaml` is what the model is told; `signatures\*.yaml` is how candidates are
found; `gold_set.jsonl` is how we are marked. A file used in the wrong place is the leakage failure the
Round 1 audit was written to catch.

## S0 — Ingest and re-ground

**What it does.** Reads hand-off #2, re-checks every quote against the frozen source text byte for byte,
and writes one flat retrieval corpus.

**In.** `HANDOFF2_DIR`, now `C:\Users\woshi\Desktop\rdtii-finale-handoff2`:

| File | Rows | What the step takes from it |
| :---- | ----: | :---- |
| `provisions.jsonl` | 766,526 | `provision_id`, `verbatim_snippet`, `snippet_char_start/end`, `doc_id`, `economy`, `law_name`, `article_section`, `location_reference`, `raw_context_before/after` |
| `laws.jsonl` | 9,130 | `law_name`, `law_number`, `source_url`, `provision_count` per act |
| `doc_status.jsonl` | 8,180 | `status`, `lane`, `source_type_final` |
| `source_text\<doc_id>.txt` | 14,722 | The frozen text the offsets point into |

**Instrument used.** None. S0 is pure arithmetic on bytes.

**The grounding check**, `ingest.py` around `:154` onward: for each record, read
`source_text[snippet_char_start:snippet_char_end]` and compare with `verbatim_snippet`. Round 1 got
411,986 of 411,986 exact. Extraction re-checked the new hand-off on 18,000 sampled records with zero
mismatches, and S0 re-checks all 766,526 for itself. **This is the one claim the whole submission's C2b
rests on, and it is re-derived here rather than trusted.**

**Out.** `data\index\prefilter_corpus.jsonl`, one line per provision, and `doc_meta.json`. The corpus
line is the provision flattened into a single searchable string, metadata-prefixed so a law's name and
section are searchable but cannot swamp the text:

```json
{"provision_id": "sg-pdpa2012-001#s.26(1)", "doc_id": "sg-pdpa2012-001", "economy": "SG",
 "text": "Personal Data Protection Act 2012 | s.26(1) | Part 6 — CARE OF PERSONAL DATA, s.26, p.33 :: was collected is no longer being served by retention of the personal data; and\n(b) retention is no longer necessary for legal or business purposes.\nTransfer of personal data outside Singapore\n26.—(1)  An organisation must not transfer any personal data to a country or territory outside Singapore except in accordance with requirements prescribed under this Act…"}
```

Note that `text` carries the surrounding context, not only the snippet. Retrieval searches the
neighbourhood; the quote stays the snippet.

**Scale.** Round 1's corpus file was 502 MB for 411,986 rows. At 766,526 expect roughly 0.9 to 1.0 GB.

**What changes for the finale.**

1. **`HANDOFF2_DIR` must be set.** It defaults to `..\handoff2`, which still holds Round 1's July output.
   A run that forgets it reads 411,986 old provisions over three economies and looks successful. S0
   should assert the expected provision count and economy set at start-up and stop.
2. **`laws.jsonl` is one row per act now.** `ingest.py:121` does `doc_meta[r["doc_id"]] = {...}`, a plain
   assignment. Timor-Leste has 2,879 acts across 1,921 documents, so the last act of each gazette issue
   overwrites its siblings and `doc_meta` ends up naming the wrong law for every issue that carries
   several. Key on `(doc_id, act_index)`, or read law identity from the provision record, which carries
   its own `law_name` and `law_name_en`.
3. **The contract is 0.3.0.** The vendored `provision.schema.json` in this stage still has
   `economy` as an enum of three, a `doc_id` pattern of `^(sg|au|my)-`, and `additionalProperties:
   false` against 27 new fields, so it rejects every record extraction now emits, Singapore's included.
   The corrected copy is on branch `p2-extract-contract-0.3.0`.
4. **Schema checking is currently a warning.** `ingest.py:107-116` catches every exception and prints,
   and validation runs on every Nth record. For a contract change this size it should be a gate.
5. **New fields to carry forward**, because later steps need them and nothing else will fetch them:
   `citation_confidence`, `article_number_as_read`, `law_name_en`, `law_name_en_source`, `act_index`,
   `act_count`, `language_of_source`, `in_official_database`, `legal_status`, `document_kind`.
6. **`scope`, `data_type` and `obligation_type` are null on all 766,526 records.** Any code that reads
   them is now reading nothing.

## S1 — Retrieval: the indicator becomes the query

**What it does.** Instead of asking "what does this provision mean", it asks, for each indicator, "which
provisions look like you?" Two independent engines score the whole corpus.

**In.** `prefilter_corpus.jsonl`, and the instrument's signature file per indicator.

**Instrument used.** `signatures\<ID>.yaml`, assembled by `prefilter\queries.py:18` into one query
document per indicator. For 6.4 the file gives:

```yaml
indicator: '6.4'
name: Conditional flow regimes
keywords: [unless, except in accordance, adequate level of protection, comparable standard of
  protection, adequacy, consent of the data subject, prior approval, security assessment,
  standard contractual clauses, binding corporate rules, transfer impact assessment, …]
definition_text: 'Cross-border data transfer is permitted only if conditions are satisfied… The
  drafting is often a default prohibition with exceptions — that pattern is a conditional flow
  regime, not a ban, because a compliant transfer path exists.'
negative_signals:
  - complete prohibition with no compliant path -> 6.1
  - conditions applied to government data are not scored
```

The query is the indicator's definition plus its keywords plus two exemplar impacts. Everything the
model will later be asked to judge is already written down here, which is why retrieval and judgement
agree on what an indicator means.

**The two legs.**

| Leg | Code | How it works | What it catches |
| :---- | :---- | :---- | :---- |
| Sparse | `prefilter\bm25.py`, `bm25s`, `TOP_K = 50_000` | Term frequency over an English stemmer with English stopwords | Terms of art. s.26(1) ranked **#39 of 319,655** for 6.4 on keywords alone |
| Dense | `prefilter\dense.py`, `BAAI/bge-m3`, 512 tokens, fp16 memmap | Cosine similarity over embeddings | Paraphrase. "shall not disclose to a place beyond the borders" matches "cross-border transfer" with no shared word |

**Out.** `data\index\bm25_top.npz` and `dense_top.npz`, each holding per indicator the top 50,000 corpus
row indices and their scores, plus `embeddings.f16.npy`, which is the expensive artifact.

**Scale.** 766,526 rows × 1,024 dimensions × 2 bytes is about 1.6 GB of embeddings. **Round 1 encoded
412,565 rows in about 1 h 53 m**, inferred from the index file timestamps of 2026-07-18 (embeddings
opened 11:52:12, `embed_meta.json` and `dense_top.npz` written 13:44:46), which is roughly 61 rows per
second. At 766,526 rows that is **about 3 h 30 m**, once, resume-safe through `embed_meta.json`. The
BM25 leg over the same corpus took about 29 seconds.

**What changes for the finale. This is the step the three new economies break.**

1. **BM25 cannot read Lao or Chinese at all.** `bm25.py:33` builds `Stemmer.Stemmer("english")` and
   tokenizes with `stopwords="en"`. Tokenization splits on spaces and punctuation. **Lao and Chinese do
   not put spaces between words**, so a whole sentence becomes one token and matches nothing. This is
   not "weaker recall", it is a leg that returns noise for 91,560 provisions. Portuguese is tokenized
   correctly but stemmed by the wrong language, and the keywords are English regardless.
2. **The dense leg is the one that can work.** BGE-M3 is trained cross-lingually, so an English query
   can retrieve Lao or Chinese text. That has to be measured, not assumed, and it is the first
   experiment.
3. **Lao text is about 94% character-accurate.** Retrieval searches OCR output. A keyword leg is more
   fragile under character noise than an embedding leg, which is a second reason the balance between
   the legs should differ by economy.
4. **`main.py:575-577` runs the BM25 leg only** and writes an empty dense stub, deliberately, to avoid
   downloading the embedding model. On the interface's run path today, a Chinese or Lao run therefore
   retrieves nothing usable.

## S2 — Selection: fusion, bands and caps

**What it does.** Merges the two rankings, then decides, per economy and per indicator, which provisions
are worth paying for.

**In.** Both `.npz` files, the corpus metadata, and the gold set for the recall gate.

**Instrument used.** `gold\gold_set.jsonl`, for the gate only, and never as a selection input. The
distinction is the leakage line: the gate measures whether organic retrieval found the host's rows; it
cannot add them.

**How, `select.py`.**

- **Fusion**, `:70-75`: reciprocal rank fusion with `RRF_K = 60`, summing `1/(60 + rank)` across both legs.
- **Hint boosts**, `:76-83`: a provision extraction tagged `conditional` gets a 35% boost toward 6.4.
  **These are now dead** — every tag is null — so fused rank alone decides.
- **Bands and caps**, `:103-112`. Per economy and indicator, the top N by fused score go to the
  **direct** band, straight to the mapper. The next 3N above `PREFILTER_FLOOR = 0.008` go to the
  **gray** band, which gets a cheap screen first.

| Indicator | 6.1 | 6.2 | 6.3 | 6.4 | 7.1 | 7.2 | 7.3 | 7.4 | 7.5 | Sum |
| :---- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Direct cap per economy | 500 | 300 | 200 | 500 | 150 | 200 | 600 | 200 | 600 | **3,250** |

**This table is the cost control of the entire stage.** 3 economies × 3,250 = 9,750 direct pairs in Round
1, and 29,250 gray. The corpus can triple without changing either number.

**Out.** `out\select\direct_pairs.jsonl`, `gray_pairs.jsonl`, `select_report.json`.

**Worked example.** s.26(1) entered **seven** candidate pairs, six direct and one gray:

```json
{"provision_id":"sg-pdpa2012-001#s.26(1)","indicator":"P6-I4","rrf":0.031400,…}   direct, top of cell
{"provision_id":"sg-pdpa2012-001#s.26(1)","indicator":"P7-I3","rrf":0.029514,…}   direct
{"provision_id":"sg-pdpa2012-001#s.26(1)","indicator":"P6-I1","rrf":0.022344,…}   direct
{"provision_id":"sg-pdpa2012-001#s.26(1)","indicator":"P6-I2","rrf":0.017109,…}   direct
{"provision_id":"sg-pdpa2012-001#s.26(1)","indicator":"P7-I1","rrf":0.016002,…}   direct
{"provision_id":"sg-pdpa2012-001#s.26(1)","indicator":"P7-I4","rrf":0.006889,…}   direct
{"provision_id":"sg-pdpa2012-001#s.26(1)","indicator":"P6-I3","rrf":0.002489,…}   gray → triage
```

Read the first and third lines together. The ban indicator 6.1 is **kept deliberately** alongside the
conditional-flow indicator 6.4, even though 6.4 scores higher. Retrieval is not allowed to resolve the
ban-versus-conditional trap on a similarity score; the mapper resolves it with the full text in front of
it. Retrieval's job is to lose nothing.

**The recall gate**, `:124-174`: for every gold row whose cited law exists in the corpus, its
(document, indicator) pair must appear somewhere in direct or gray. Round 1: **37 of 37, recall 1.0**,
with the allowlist off.

**What changes for the finale.**

1. **The gate's law matcher deletes non-Latin names.** `_norm()` at `:184-186` runs
   `re.sub(r"[^a-z0-9 ]", "", …)`, so a Chinese or Lao law name normalizes to an empty string and can
   never match. It must use `law_name_en`, which extraction now fills on 100% of records.
2. **Caps at 61 indicators.** There is no cap for the other 52. At the current average of 361 per
   indicator, six economies at 61 indicators is about 132,000 direct and 396,000 gray pairs, against
   Round 1's 9,750 and 29,250.
3. **The dead hint boosts** should be removed or replaced. A useful replacement: prefer
   `citation_confidence: exact` over a repaired citation when fused scores tie.
4. **The per-economy cap is uniform, and the economies are not.** 3,250 slots is 1.1% of Australia's
   302,243 provisions and 7.8% of Lao's 41,534. Whether that is right is measurable against the gate.

## S3 — Triage: a cheap, lenient screen

**What it does.** Asks a cheap model one yes/no question per gray pair, biased toward keeping.

**In.** `out\select\gray_pairs.jsonl` plus the provision text.

**Instrument used.** `signatures\<ID>.yaml`, for the indicator's one-line definition. Note the glob at
`triage\haiku.py:46` is `P*.yaml`, which matches no decimal-named file.

**The prompt**, in substance: here is a provision, here is what indicator X asks; could this be evidence?
Answer NO only if it is clearly unrelated. **Errors default to keep.** Precision is bought later, by an
expensive model; recall lost here can never be recovered.

**Out.** `out\triage\haiku_results.jsonl`, one line per pair:

```json
{"provision_id": "sg-pdpa2012-001#s.26(1)", "indicator": "P6-I3", "economy": "SG",
 "keep": false, "why": "Provision concerns data transfer restrictions, not infrastructure requirements."}
```

That is the gray pair from S2 being correctly killed: s.26(1) is not an infrastructure requirement.

**Scale.** Round 1 judged 29,250 pairs and kept 5,762, or 20%, for a figure of $44.54 which **the cost
ledger discloses as unevidenced** — no surviving artifact carries it. Treat it as an order of magnitude,
and make the new ledger record it properly.

**Two lanes.** Production used Haiku. A local lane exists at `triage\local.py:84`, posting to Ollama with
raw `httpx`, at $0. The A/B that chose Haiku measured the local model missing 16% of what Haiku keeps.

**What changes for the finale.** Whether this step earns its place at all is a phase-2 question: it costs
money and latency to save mapper calls, and the mapper is prompt-cached, so the saving is smaller than it
looks. For Lao the local model is weakest exactly where the text is noisiest.

## S4 — Mapping: the schema is the method

**What it does.** One call per provision, carrying all of that provision's candidate indicators at once,
against the full codebook.

**In.** Direct pairs plus kept gray pairs, grouped by provision.

**Instrument used.** This is where the codebook is actually spent.

- **`indicators.yaml`**, rendered by `prompt.py:18` into a byte-stable cached system prefix. Only nine
  keys per block are rendered, `:36-38`: `id`, `name`, `question`, `definition`, `scoring`,
  `scoring_tree`, `coding_rules`, `exceptions`, `disambiguation`. `review_notes` is excluded by
  construction, which is what the instrument notice requires.
- **`policies.yaml`**, `:41-43`: `scoring_policy`, `edge_cases`, `measure_inclusion`.

For 6.4 the model is given, among other things, the scoring tree and this disambiguation line:

> TRAP (mirror of the 6.1 trap): 'prohibited unless conditions are met' — the default-prohibition +
> exception drafting pattern (e.g. Singapore PDPA s.26) — is 6.4, NOT a 6.1 ban. Classify by whether a
> compliant transfer path EXISTS.

**Why the prefix is byte-stable.** Fixed order, no timestamps, `lru_cache`. Stability is what makes
prompt caching pay: Round 1's Singapore run read 38.4M cached tokens, which is why mapping came to
$0.016 per provision.

**The user turn**, `prompt.py:47-57`: provision id, economy, law, section, the text as
`context :: snippet :: context` **truncated to 6,000 characters**, the candidate list, and the
instruction that `verbatim_quote` must be an exact substring.

**The schema is the real instrument**, `mapping\schema.py`. Pydantic field order forces the model through
a human coder's procedure before it may answer:

```
core_legal_question_answer → who_is_regulated → conditions_and_exceptions
→ trap_checks (5 booleans) → verdicts[] (one per candidate)
```

The five booleans are `conditional_path_exists`, `retention_is_minimum`, `government_data_only`,
`provision_in_force`, `sectoral_scope`. They exist because the host named "answering the wrong core legal
question" as its first error class.

**Out.** `out\map\verdicts_<ECON>.jsonl`. The real verdict for s.26(1), six candidates in one call:

```json
"core_legal_question_answer": "S.26(1) requires organisations to ensure transferred personal data
  receives protection comparable to PDPA standards as a condition of cross-border transfer — a
  conditional flow regime, not an outright ban; s.26(2) confirms exemptions are available, and the
  surrounding text about retention (no longer necessary) is a maximum-period, not minimum-period, rule."
"trap_checks": {"conditional_path_exists": true, "retention_is_minimum": false,
                "government_data_only": false, "provision_in_force": true, "sectoral_scope": false}
```

| Candidate | applies | score | Why the model said so |
| :---- | :---- | :---- | :---- |
| P6-I1 ban | **false** | n/a | "Conditional path exists … not a per se ban; classified under P6-I4 instead" |
| P6-I2 storage | false | n/a | "No requirement to retain a copy domestically" |
| **P6-I4 conditional** | **true** | **1** | "Conditional flow regime covering personal data horizontally" |
| P7-I1 framework | true | 0 | Inverted polarity: a framework EXISTS, so the economy does not lack one |
| P7-I3 retention | false | 0 | "This is a maximum/retention-limitation principle … not a minimum retention period" |
| P7-I4 DPO/DPIA | false | n/a | "No DPO or DPIA requirement appears in this provision" |

Two traps fired correctly in one call. That is the design working.

**Grounding**, `runner.py:115`: `grounded = _ws(x.verbatim_quote) in _ws(rec["text"])`, whitespace
collapsed, recorded as `quote_grounded_ws`. **The model writes the quote and the code checks it
afterwards.** This is the single most important line in the stage for engine choice: in Round 1 the Haiku
mapper grounded 43.4% and DeepSeek 48.4% and 71.7%, against a 98% bar.

**Two transports.** `runner.py` is the live lane. `batch_runner.py` is the Anthropic Batches lane at a
50% discount, used for bulk; it constructs `anthropic.Anthropic()` directly at `:174`, `:199` and `:220`,
so it is Engine A only by decision M3.

**Cost.** $0.016 per provision live, $0.0088 batch, both measured.

**What changes for the finale.** Decimal IDs in the trap text, which the model reads; one prefix of the
nine automated blocks, measured at 31,915 characters against Round 1's 25,974; the grounding fallback so
an ungrounded quote is replaced by the provision's own snippet rather than shipped; and a decision about
whether the 6,000-character truncation is right for Chinese articles, which are long.

## S5 — Blind verification

**What it does.** Re-judges every fire with a second model that **never sees the first model's
reasoning**, only the provision and the indicator question. Disagreement goes to a third model, and
two of three decides.

**In.** Every `applies: true` verdict from S4. **Out.** `out\verify\verified_<ECON>.jsonl`.

Both outcomes on our example, from the real file:

| Fire | Blind verifier | Tiebreak | Result |
| :---- | :---- | :---- | :---- |
| s.26(1) × **6.4**, score 1 | agrees | — | **verified**, and this row reaches the workbook |
| s.26(1) × **7.1**, score 0 | disagrees: "a transfer condition, not framework-scope evidence" | sides with the verifier | **overturned**, fire deleted |

**Scale.** Round 1 overturned about a third of all fires: Singapore 399 of 1,210, Malaysia 281 of 807,
Australia 1,025 of 2,827. Zero three-way splits. Those 1,700-odd deletions are false positives that never
reached a judge, and the overturn rate is the best single piece of evidence that the pipeline is not
simply agreeing with itself.

## S6 — Rollup to an economy score

**What it does.** Turns verified provision-level fires into one score per indicator per economy.

**Rules.** Maximum over verified scores for most indicators; an escalation rule where several half-point
measures together justify a 1; and **7.1 and 7.2 are economy-level**, answered once with dedicated
framework calls rather than per provision. **Out.** `out\rollup\economy_scores_<ECON>.json`:

```json
"P6-I4": {"score": 1.0, "basis": "max over 13 verified fires", "evidence_rows": 13, "pending": 0}
"P7-I1": {"score": 0.0, "basis": "The evidence shows a single comprehensive horizontal statute, the
  Personal Data Protection Act 2012, covering consent (s.13), notification (s.20), collection/use/
  disclosure limitations (s.18), access and correction (s.21-22)… SG has a comprehensive framework",
  "controlling_law": "Personal Data Protection Act 2012", "evidence_rows": 13}
```

Note that 7.1 scoring 0 is the good outcome: the indicator measures the **lack** of a framework, so
inverted polarity means a 0 is a pass. The polarity list lives in `policies.yaml` under
`scoring_policy.polarity`, and the code currently keeps its own copy.

## S7 — NEW against KNOWN

**What it does.** Tags each verified row against the 2025 baseline the host supplied. KNOWN means the
host already has it; NEW means the tool found something the baseline does not carry.

**In.** Verified fires, plus the baseline workbook parsed by `discovery\baseline.py`.

**Out.** `out\discovery\newknown_<ECON>.jsonl`, with the match evidence recorded:

```json
{"provision_id": "sg-pdpa2012-001#s.26(1)", "indicator": "P6-I4", "discovery_tag": "KNOWN",
 "baseline_match": "r1-sg-036", "match_evidence": "law+section match (s.26)", "law_fuzzy": 1.0}
```

**What changes for the finale.**

1. **Match on instrument name and section, never URL.** The host's own 2025 rows cite the main law
   database zero times out of 172 in Malaysia, twice of 147 in Russia. A URL join would score those at
   zero and measure the wrong thing.
2. **`law_name_en` makes cross-language matching possible.** The host lists Lao and Chinese laws in
   English; our corpus holds them in Lao and Chinese. Extraction fills the English title on 100% of
   records, which removes the blocker recorded on 22 September.
3. **Baselines by economy.** Round 1 sheets for SG, MY and AU; Round 2 sheets for China and Lao PDR;
   **Timor-Leste has no sheet at all**, so every row there is NEW and the Notes column should say why.

## The three non-English cases, and what each one does to this workflow

### China — clean text, English-normalised citations

PIPL Article 3, from `cn-cacd5388753-001`:

```json
{"provision_id": "cn-cacd5388753-001#Art. 3", "article_section": "Art. 3",
 "citation_confidence": "exact", "page": null, "language_of_source": "zho",
 "location_reference": "第一章 总 则, 第三节 国家机关处理个人信息的特别规定"}
 snippet: 第三条 在中华人民共和国境内处理自然人个人信息的活动，适用本法。…
```

- The text is native digital, not OCR: **China is the cleanest of the three**.
- `article_section` is normalised to `Art. 3` while the text prints 第三条. Good for the workbook, which
  wants a citation a reader can follow; worth confirming the host accepts the Latin form for a Chinese
  act.
- `page` is null because the source is HTML, so Location Reference falls back to the chapter heading.
- One spot-check to make: the `location_reference` above pairs Chapter 1 with a Section 3 heading that
  belongs to a later chapter. One sample is not a finding, but heading tracking is worth a look.
- BM25 returns nothing usable here. The dense leg carries China.

### Lao PDR — where the risk actually is

`la-la1216-001#Art. 2`, from the Law on Electronic Data Protection:

```
ມາດຕາ 2  ລັດຖະດ່າລັດສະບັບນີ ມີຜົນສັກສິດ ນັບແຕວັນລົງລາຍເຊ້ນ ເປັນຕົນໄປ. … ອັນທີ ,..]2.40າ5/ໄໂໃ
citation_confidence: "exact"
```

Three things to take from this one record:

1. **`citation_confidence: exact` does not mean the text is good.** It means the article number was
   printed on the page rather than reconstructed. This snippet is a garbled cover page. The two
   guarantees — a quote is a true substring of stored text, and stored text matches the page — are
   different, and only the first is proven.
2. **Article numbers repeat.** The ids run `#Art. 2` and `#Art. 2~2`, the tilde marking a second
   occurrence, because the file contains the National Assembly resolution pages as well as the law.
3. **About 6% of Lao characters are wrong, and one article number in seven was repaired from position.**
   A Lao row filed with a repaired citation is a direct C2b risk, so S9 should prefer exact-citation rows
   for the workbook and mark the rest.

### Timor-Leste — several acts in one file

`tl-mdtdlus-001#a1#Art. 1`, `act_index: 1` of `act_count: 3`:

```
Artigo 1.º A presente lei estabelece as medidas de tutela da legalidade urbanística…
location_reference: "CAPÍTULO I, p.1"
```

The act index is inside the provision id (`#a1#`), which is what keeps three acts in one gazette PDF
apart. **`act_index` is null on 68,867 Timorese provisions, 36%**, because extraction withheld rather
than guessed. Those rows can still be mapped, but they should not be filed in the workbook, because the
law name cannot be pinned to the article with certainty, and a real act cited to the wrong place scores
zero.

## Appendix: identifier conventions

| Form | Example | Meaning |
| :---- | :---- | :---- |
