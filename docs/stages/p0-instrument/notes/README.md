# notes

Working notes for the instrument task, one file per question you had to answer.

Put here what you learned from the RDTII 2.1 guide, the internal guide, the methodology sheet and
the host Indicator Reference sheet. Four things are worth writing down.

| Write down | Why |
| :---- | :---- |
| What an indicator actually asks | The Category line is a label, not a definition |
| Where two indicators overlap | Disambiguation is the whole value of the instrument |
| Which statute wording triggers which branch | A scoring tree is only as good as its trigger words |
| The page or cell you took it from | A judge will ask |

Draft scoring trees and trap wording here before they go into the real file at
`instrument\output\indicators.yaml` in this workspace (since 2026-09-13, decision D9). Keep the
reasoning that did not survive. The disambiguation between two confusable indicators is usually the
thing you will need to defend to a judge.

Not allowed in `notes\`: source code, copies of engineering docs, or licensed text from the framework
PDFs. Point at the path where the real artefact lives. The instrument itself sits in `instrument\`,
and host documents in `sources\`.
