RDTII Rocky
1Introduction

RDTII Rocky is a tool that maps an economy’s laws to the RDTII indicators, in three stages:

  1. Scraping: collects the economy’s laws from its official portals.
  2. Extraction: splits them into numbered provisions.
  3. Mapping: maps each provision to the indicators, with the quote, the score and a review by a person.

The instrument: the RDTII rules as a rulebook

What the models read at every step. This is how the RDTII rules become something a model can apply, the same way for every indicator.

What a rulebook holds
Questionthe one question a provision must answer Definitionwhat the indicator measures, from the Guide Scoresthe scores the indicator allows Scoring treewhich case gives which score Coding ruleswhat counts, and what does not Exceptionswhat is never scored Trapslook-alikes that belong to another indicator Count rulewhen several measures raise the economy’s score Absencethe score when nothing is found
Example: one indicator, 6.4 Conditional flow regimes
Guide pp. 52…54→the rulebook of 6.4
QuestionIs cross-border data transfer permitted ONLY IF conditions are met: consent, adequacy, contracts or government approval? DefinitionThe conditions a business must satisfy to transfer data across borders. Who decides, the person, the business or the Government, does not change the score. Scores1 · 0.5 · 0 Scoring tree1 the conditions cover personal data, or apply across all sectors. 0.5 non-personal data, or a specific set of data only. 0 no condition attached. Coding rulesCommercial transactions only. A condition on personal data scores 1 even in one sector. Every kind of condition scores the same. ExceptionsConditions on government data are not scored. Traps“Prohibited unless conditions are met” is 6.4, not a 6.1 ban: a way to transfer exists. Count ruleNone for 6.4. (Under 6.1 and 6.2, two or more half-point measures score 1.) AbsenceNothing found scores 0.

BQuick screen

Removes the unrelated among the borderline, the candidates that scored below 0.65. Above that, a candidate goes straight to C. A cheap model is enough.

we sendThe indicator’s definition and the provision: could it be relevant?
fast model (Haiku 4.5 in the finale)YES or NO.
CCareful reading

Decides each candidate against the rulebook: applies or not, with a quote and a score. Needs a strong model.

standing instructionThe rulebook of every indicator in the run.
we sendThe provision and its candidate indicators. Answer the question, run every trap check, give one verdict per candidate.
reading model (Sonnet 5 in the finale)Per indicator: applies or not, score, quote, reason.

  • Tag. KNOWN if the row is in the Round 1 baseline, NEW if not.

5Before you start

  • The health dots in the header: Ollama, Tesseract, Chromium, Key, Stages. Green means ready.
  • A hosted provider (Claude, DeepSeek, Kimi, ChatGPT) needs its API key under Engine API keys, at the top of the Mapping page. A key is held in memory for this session and never written anywhere.
  • Qwen, local, needs Ollama running with the model pulled.
  • Every page: Set up, Run, Output. Press Check before Start; Start unlocks when no check fails. Every Output block opens its folder.
  • The first mapping run on a new extraction output builds the index. The meaning index needs a one-time model download.
