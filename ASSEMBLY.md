# How this repository was assembled

Created 2026-09-29. **This is the submission repository.** The release tag cut here is what a marker
deploys and what runs on 15 October, so what is in this tree is the submission and what is outside it
is not.

It is a fresh repository rather than a branch of the development one, for one reason:
`rdtii-rocky-finale` carries 77 files of ESCAP's own material in its git history, including the Round 1
and Round 2 databases, the methodology workbook, the output templates and the host's take-home
assignments. The submission requires a public repository, and deleting those files after publishing
does not remove them from history. This tree starts clean.

**The development history stays in `rdtii-rocky-finale` and in the five workshop folders.** Do not
delete them. They are the record of how the work was done and can be shown on request.

## What is still to come, and from exactly where

**1. `stages/p1-scrape/` — a merge, not a copy.** Three parts have to come together:

- the crawler engine from `rdtii-rocky-finale` at `stages/p1-scrape/`, which is where the shared code
  lives;
- the per-economy adapters from `rdtii-finale-1-scraping\countries\<cc>-<name>\`, which is where the
  six economies were actually built, 34 MB across six countries plus a template;
- **four hand-backs the workshop never applied to the engine**: `cryptography==44.0.0` in
  `requirements.txt`, the deletion of `tests/test_my_selection.py`, and Timor-Leste's and Lao PDR's
  engine changes covering the economy code, the adapter registry, the manifest schema and the slug.
  One Lao test is an expected failure until the last of these lands.

`rdtii-finale-1-scraping\outputs\` is 19 GB of retrieved documents and does **not** travel. It is
regenerated by running the crawler.

**2. `stages/p3-map/` — from the branch, not from the workshop.** The mapping code exists only in
`rdtii-rocky-finale` on branch **`w2-mapping-finale`**, 56 files under `src` and `config`, 47 commits
ahead of `finale`. The mapping workshop holds 11 probe scripts and no stage code, so copying from the
workshop would lose every commit including today's.

Two cautions. Take it from `w2-mapping-finale` and never from `finale`, which is 47 commits stale. And
there is one uncommitted file on that branch, `stages/p3-map/src/p3map/output/excel_export.py`, which
must be committed first or it will not be in what you take.

Mapping is still being modified as of 2026-09-29. Copy when it settles.

**3. `submission/` — the filed rows.** 318 rows exist at
`rdtii-finale-p3-runs\run_2026-09-27\out\submission\`, of which 263 carry a scored provision. The host
template holds at most 101, so they must be curated and the selection rule written into the Word
document. Two suggested rules from the mapping stage: exclude Timorese rows from multi-act gazette
files unless they are the first act, which removes 33 of 65, and prefer exact citations over repaired
ones.

## A note on the OCR language packs

`stages/p2-extract/fixtures/` is 82 MB, almost all of it Tesseract language packs, which ship in the
repository by decision D7 so that a clean deploy needs no download. 58 MB of that is the `best` packs
and 15 MB the `fast` packs. The measured choice for Lao was **`fast`**, on the evidence that it matches
`best` to within half a point at half the time and half the size. If repository weight matters, the
`best` packs are the first thing to drop, and the decision should be recorded rather than silent.
