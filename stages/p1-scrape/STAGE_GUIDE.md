> **Read this first — what changed for the submission, 2026-09-29.** This document is Round 1's,
> written when the stage crawled three economies. Four things about this tree differ from what it
> describes, and the differences matter before you run anything:
>
> - **Six economies, not three.** Singapore, Malaysia, Australia, **Timor-Leste**, **Lao PDR** and

> - **`handoff1_v2/` is not in this tree.** Round 1's corpus was output and did not travel. Where a
>   command below says `handoff1_v2/`, the evidence is now under **`handoff1/<CC>/<CC>_corpus_<date>/`**,
>   one folder per economy. `handoff1/README.md` is the guide to it.
> - **`reference/` is not in this tree.** Those two CSVs were ESCAP's own law-to-URL map, and this
>   repository is public at the release tag. A reviewer with their own copy places it wherever they

> - **The documents are not in this tree** — 19 GB of retrieved law, regenerated by crawling. So
>   `scrape.py --validate` reports `local_path does not resolve on disk` for every row until a crawl

## What this stage is

P1 crawls the **live official legal portals** of the three economies —
Singapore (sso.agc.gov.sg + regulators), Malaysia (lom.agc.gov.my +
regulators), Australia (legislation.gov.au + regulators) — and retrieves the
complete, **pillar-agnostic** statute corpus as raw bytes (native PDF, scanned
PDF, HTML). No OCR, no interpretation — that is P2/P3. Its product is
**Hand-off #1**: a JSON-Schema-gated manifest keyed by stable `doc_id`, the
raw files, per-document provenance sidecars, and an append-only crawl log.

Corpus state: **v2.4 — 2,706 manifest rows = 2,673 current documents
(SG 536 / MY 869 / AU 1,268) + 33 superseded-annotated** (the multi-volume
re-fetches; see below). Ledger: `docs/CORPUS_VERSIONS.md`.

## What's shipped here vs. regenerated

| Shipped in this repo | Usage |
|---|---|
| `handoff1_v2/manifest.jsonl` + `manifest.csv` | The 28-field, contract-0.2.0 manifest — one row per document: doc_id, law name, URL, sha256, retrieval method, access date, supersession annotations. **The authority on what the corpus contains.** |
| `handoff1_v2/crawl_log.jsonl` | Append-only log of every fetch **including failures and corrections** (e.g. the BNM RMiT HTTP-202 entry plus its disclosed `correction: true` follow-up). |
| `handoff1_v2/cost_report.json` | Measured crawl cost/footprint. |
| **NOT shipped: `handoff1_v2/raw/**`** (~1.85 GB) | The corpus bytes + `.headers.json` sidecars — regenerable by one command (below); sha256 for every file is in the manifest, so a regenerated corpus is verifiable byte-for-byte. |

## Workflow (how a crawl runs)

1. **Discovery** — per-portal enumeration (SG: union of ASC+DESC browse
   listings; MY: act-detail pages 1–900; AU: register OData, 4,747 in-force
   acts filtered to principal). Deliberately enumerative, not curated.
2. **Fetch** — politeness-limited live retrieval; every attempt (success or
   failure) appended to `crawl_log.jsonl`.
3. **Store** — raw bytes + `.headers.json` sidecar + sha256.
4. **Manifest** — one schema-gated row per document; supersession annotations
   instead of deletions (nothing is silently rewritten).
5. **Validate** — `scrape.py --validate` gates row counts, schema, and
   supersession consistency.
6. **Versioning** — corpus changes ship as additive versions (v2.0 → v2.4)
   with a ledger entry; the multi-volume fix (33 AU acts re-fetched complete,
   acceptance 33/33 machine-checked against each compilation's own declared
   volume count) is the worked example: `docs/AU_HTML_TRUNCATION_AUDIT_2026-07-17.md`.

## Commands

```
# environment (Python 3.12, pinned deps)
pip install -r requirements.txt
python -m playwright install chromium

# live-crawl proof, ~1 minute (3 portals, one canonical URL each)
python scrape.py --smoke

# deterministic small slice (~5 min)
python scrape.py --economy SG,MY,AU --seed-laws-only --out handoff1

# full corpus (~6–8 h, resumable; re-runs skip already-retrieved laws)
python scrape.py --economy SG,MY,AU --scope all --out handoff1

# the validate gate
python scrape.py --validate handoff1_v2/manifest.csv

# tests
pytest
```

## Hand-off to P2

P2 consumes `handoff1_v2/manifest.csv` + `raw/` (paths via `.env`,
sibling-relative defaults). The manifest is the authority; superseded rows are
annotated, never deleted.
